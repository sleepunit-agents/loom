Models and accounts

Which model a body runs on, and the accounts it draws from. The runtime handles model accounts, runners and which model a body uses.

  • Gives each agent a primary conversational model.
  • Shares each account's capacity across the agents that draw on it.
  • Starts each body through a runner on a worker machine.
  • Records the model each job asked for and each turn used.

How it works

Models, quota, runners and account sign-in

Per agent, per account

  • modelchosen per agent
  • capacityshared per account and window

The primary conversational model is per agent. Capacity is shared per actual subscription, account and window, so two agents on one account draw down the same allowance.

Quota

Fuel58% of the weekresets Thu

An account's use is counted in windows that reset, such as five hours and seven days. A reserve of about five percent is the starting point. It can be lent near a reset when the forecast is safe, and is not a rigid floor.

Runners

  • claude
  • codex

A runner is the program on a machine that starts bodies. Loom keeps models, series, providers and harnesses distinct, and roles can be added through configuration.

Signing in to an account

Kept apartA separate private programThe runtime calls it as a configured command.

Signing in to a model account is handled by a separate private program. The runtime handles which account, which runner and which model a body uses.

Who can see this

owner
  • aThe owner and household owners. They see everything about an account: usage, when it resets, and where it is signed in.
  • bAnyone else. They see only the account's label and a coarse level: plenty, getting full, or almost full.
  • cChecked at the door. Loom applies this to callers from outside: a person, an agent, a machine, someone's own program. Loom's own parts read without asking.
