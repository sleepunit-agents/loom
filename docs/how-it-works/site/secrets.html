Secrets

Credentials agents need, and who may use each one. A secret is a named credential, such as a GitHub token.

  • Keeps each value encrypted, in a separate file held by a separate small program.
  • Lets an agent request a secret, and a person or a rule answer.
  • Grants access for a set time, to one agent or to one job.
  • Writes down every time a value is handed out.

How it works

Requests, rules, the key holder and the use record

Ask, answer, grant

pendingallowallowed

An agent requests a secret with a reason and a length of time. A person answers, or a rule answers for them. A yes creates a grant that lasts a set time.

Rules

  • askask each time
  • autogrant automatically
  • nevernever grant

A rule is a standing answer for one secret, for the agents it lists. Answering always makes a rule. The household has a default for a secret with no rule of its own.

The key holder

A separate small programValues, encrypted, in a separate fileLoom's main database holds only names and descriptions.

A secret's value never sits in loom's main database. The app can set or replace a value and cannot read one back.

Every use written down

  1. secret_usesgithub-token to art, 9:15 AM, released
  2. secret_changesreplace, by jonathan

Every time a value leaves the key holder, loom records which secret, for which agent and job, and when. Each time a value is set, replaced or removed is recorded too.

Who can see this

  • aOwners manage them. Household owners manage Settings, which is where secrets, requests and grants are.
  • bValues are never shown. A value is write-only. Nobody reads one back in the app.
  • cAgents. An agent is handed a value only under a grant, and each hand-off is recorded.
  • dChecked at the door. Loom applies this to callers from outside: a person, an agent, a machine, someone's own program. Loom's own parts read without asking.
