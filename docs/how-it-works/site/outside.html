Outside programs

An outside program has one door: the API, with a token. The command line, the web app, agents and anything outside loom call the same operations through the same permission check.

  • One API for the command line, the web app and agents.
  • A token says who is calling and what it may reach.
  • Someone else's program sees only what a household owner granted it.
  • The phone and any other interface are callers like any other.

How it works

Tokens, one program, replaceable parts and the phone

Narrow tokens

  • a memberwhat that person may see
  • an agenta token that is one agent
  • a runneronly the jobs assigned to it
  • a programonly what an owner granted

Anything outside loom calls the API with a token. Someone else's program is a caller with a token: it sees only the record types and operations a household owner granted it.

One program, one data folder

Installnpm install -g @jbarket/loomaithen loom serve

There is one loom per home: one program and one data folder. Loom itself needs nothing beyond Node and npm. A machine whose worker runs houses also needs git and a container engine. A restart is an acceptable deploy.

Parts can be replaced

tasks rolefilled byone module

Each part is a module with a declared, typed interface. A role has one implementation at a time, so replacing the task store means writing another module that fills the tasks role. A bridge is replaced the same way.

The phone

After the deskThe phonecalls the same API

The phone does what the desk does, built after the desk is right. It is a caller like any other.

Who can see this

  • aChecked here. Permission is checked where something outside calls the API, and nowhere else.
  • bInstalled means trusted. Loom's own parts never ask each other for permission.
  • cThe rule. A household owner sees everything, including what is private to another member. Anyone else sees what is in their projects, plus what belongs to agents they own. Private to a member means that member plus household owners.
