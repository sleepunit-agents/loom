Loom · how it works

Everything is a conversation.

Loom is a program one household runs for itself. A few people and a few AI agents share a desk in the browser: small app windows side by side, the agents at the edge, a ticker along the top.

Whatever an agent does, it does in a conversation. You chat with it in loom. Someone talks to it on Discord or Slack. A trigger starts it. One agent hands work to another. Each of these is the same thing to loom, so conversations sit at the centre and every other part touches them.

Chat is how you control loom. Screens are for seeing. Every app also appears inline in a conversation.

Ground rules

Eight rules hold everywhere

  1. 1Chat controls, screens showYou control loom by talking to your agents. Screens are for seeing. A settings change or a dangerous action asked for in chat gets an approval card inline, with before and after. Ordinary work needs no card.
  2. 2Installed means trustedLoom's own parts never ask each other for permission. Loom checks permission only for callers from outside.
  3. 3A small team that trusts each otherThe project is the unit of sharing. No fine-grained permissions. Household owners see everything.
  4. 4Real columnsEvery fact is a named column, defined once with Drizzle. The database does the work. SQLite by default; the database is a configuration choice.
  5. 5One query endpointA GraphQL endpoint generated from the same schema. A tile names the fields it wants, and changes arrive as subscriptions over one websocket.
  6. 6Only memories are preciousAgents' memories are the one kind of data loom treats as irreplaceable. Notes come second: looked after, but not irreplaceable.
  7. 7One program, one data folderQuick for someone else to install. One API for the command line, the web app and agents. A restart is an acceptable deploy.
  8. 8Parts can be replacedEach part is a module with a typed interface, so the task store or a bridge can be swapped for another.
