Changes

Pull requests the household cares about. A change is one pull request, read from GitHub and kept as a copy.

  • Lists pull requests across the household's projects.
  • Says who each one is waiting on.
  • Shows its checks, its review and the tasks it mentions.
  • Takes your answer on a merge. The agent does the merging.

How it works

Waiting on, reading GitHub, checks and people

Who it is waiting on

  • youyour answer
  • agentready to merge
  • cichecks running
  • reviewer
  • author

For each change loom works out who it is waiting on: you, an agent, the checks, a reviewer or its author. The list is ordered that way, with finished ones last.

Reading GitHub

change_syncLast read 9:12 AM CTOne row: when loom last read, whether that failed, when it reads next.

Loom reads the pull requests in each project's repositories and keeps a copy, so the desk shows what is waiting without asking GitHub each time.

Checks and review

  • checkspassing, failing, running, none
  • reviewapproved, changes requested, required, not required
  • mergeableyes, no, unknown

Loom keeps the state of a change's checks and review, plus the names of the checks that are failing or still running.

People on it

  • author
  • reviewer
  • requested
  • assignee
  • commenter

A change lists the GitHub logins on it and the part each plays.

Who can see this

projectagent
  • aTwo labels. A change gets its project from its repository, and its agent when an agent opened it.
  • bWho sees it. A household owner sees everything, including what is private to another member. Anyone else sees changes in their projects and changes opened by agents they own.
  • cChecked at the door. Loom applies this to callers from outside: a person, an agent, a machine, someone's own program. Loom's own parts read without asking.
