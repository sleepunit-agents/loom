Tempo

Triggers: what starts work without anyone asking. A trigger fires in code and drops an item in someone's inbox. A non-empty inbox is what starts an agent or notifies a person.

  • Shows a day as a calendar, with each trigger at the time it fires.
  • Opens any trigger to show what it does, when it runs next and how its recent runs ended.
  • Shows how full each subscription was through the day, and what each run used.
  • Fires on a time, a pull request changing, an answer arriving, a job stopping or an alert firing.
  • Drops an item in an inbox, or runs an operation that needs no agent.
  • Holds an agent's triggers while the agent is paused.
The calendar

One day, four kinds, state, opening one, history and what it used

What a person sees in the Tempo tile and what they can do there.

One day

  • Dayone day, hour by hour
  • Weekseven days side by side
  • All triggersevery trigger, by its next time

Tempo opens on today, in the household's time zone. Each trigger is a block at the time it fires, and a line marks now. Above the line a block says how its run ended. Below the line it says what is coming. The arrows move one day at a time. The list at the side narrows the calendar to one kind, one state, one agent or the household's own lanes. Week shows seven days, so a trigger that runs on Sundays or on Wednesdays is on its day. All triggers lists every one by its next time, and that is where a monthly one is found. A trigger that fires many times a day sits in one row above the hours.

Four kinds

wakes an agentplan · art
a program decidesship-nag
loom itselfnightly backup
onceCheck the pump delivery

Each block is one of four kinds, with its own colour and its own word. Wakes an agent: a body of the agent does a job each time. A program decides: a small program of the household's runs with no model, and wakes an agent or tells a person only when there is something to do. Loom itself: no agent and no program of the household's, such as the nightly backup or watching model sign-ins on every machine. Once: it fires one time at a set time, and then it is spent.

No clock time

  • pull requestcoordinate
  • answerMerge when allowed
  • jobnothing waiting
  • alertalert triage

Some triggers fire when something happens, not at a time: a pull request changing, an answer arriving, a job stopping, an alert firing. They have no place on the hours. They sit in a strip above the day, each under what it waits for. When one fires, a block with a dashed edge appears at the time it happened.

State

  • standingit will fire at its next time
  • stoppedsomeone stopped it
  • heldits agent is paused
  • spentit fired once and is finished

Most triggers are standing. A stopped trigger stays on the calendar, struck through. It says when it was stopped and when it would have run next. A trigger whose agent is paused is held, and says so the same way. A one-off that has fired is spent. A run that failed or was lost is marked on its block.

Open one

a program decides · stoppedship-nagProgram: ship-nag. It checks for finished work that has not shipped. Stopped Nov 12 by jonathan. Next would have been 09:17 CT.

Click a block and it opens beside the day. It says what the trigger is for in one sentence, when it runs and when it runs next. It says what it does: the words handed to the agent, or the program's name and what it checks. It says who it runs as and for which project, which machine it needs or prefers, and which model. Its recent runs are listed with the time, how each ended, how long it took, what it used and a link to its conversation. It also says what share of the subscription's week it took over the last seven days. Run now fires it once. Stop and Start turn it off and on. To change it, ask the agent: it proposes the change, and loom shows an approval card with before and after.

The day's history

  1. 08:31plan woke art · done
  2. 07:17prowlarr-cf-check · failed
  3. 04:17knowledge-verify · lost

History lists everything that fired on the day being viewed, newest first: what fired, what it started and how that ended. A run that failed or was lost is in the list, with the reason. So is a trigger that was stopped or held at its time.

What it used

Claude subscriptionplenty92% at its fullest today

  2. 31k outtokens the model wrote
  3. peak 210kits largest context

The household runs on subscriptions, so Tempo shows no money. It shows what is scarce: each subscription's 5-hour window and its week. Above the hours, one line for each subscription says how full its 5-hour window was at its fullest today and how much of the week is used. These are the provider's own readings, so they are exact. Hours with stripes are the hours when a 5-hour window was almost full: work scheduled there was competing with a person. Hours with no stripes had room that went unused. Each run says how long it took, how many tokens the model wrote and its largest context. A trigger's share of the week is an estimate. The provider gives one reading for the whole subscription, so runs that overlap are split by their tokens. The detail is in Subscriptions.

How it works

Four parts, firing, the sweep, volume and settings

A trigger's four parts

  • sourcea time, a pull request changing, an answer arriving, a job stopping, an alert firing
  • lifespanuntil stopped, for today, the next time only
  • ownerwho set it
  • targetrun an operation, or drop an item in an inbox

A schedule is a standing time trigger. A lane is a standing time trigger with instructions. A one-off wake is a time trigger that fires once. Waiting on an approval is a once-only trigger on that answer. One trigger can be stopped and started again without touching the rest. Its words, times and label can be edited, and loom keeps what they said before and who changed them.

Fire, inbox, start

triggerfiresinboxsettlesagent

A trigger fires in code, with no model. It drops an item in the recipient's inbox. After a short settle time, a non-empty inbox starts an agent's body or notifies a person, with everything waiting at once. Pausing an agent holds its triggers.

The sweep

  1. Changes2 open, oldest 3 days
  2. Tasks4 ready, oldest 6 days
  3. Approvals1 pending, 2 hours

Each part contributes a short list of what is open and how long it has sat. One session per recipient sorts them. When nothing is open, no session starts.

Volume

  • fullthe default
  • dimone line
  • mutehidden, and always ends

Each recipient sets a volume on an inbox item. Dim returns to full when the item changes or has sat long enough. Mute ends after a week by default. A change breaks dim but not mute. Being asked by name breaks both.

Three settings

  • settlehow long an inbox waits before waking its owner
  • dimhow long before a dimmed item returns to full
  • mutehow long a mute lasts: 7 days by default

The timings are settings a person can change, each with a default. Loom keeps a row only for a person or agent that has changed them.

Who can see this

ownerfor an agent or a personproject
  • aWhat it carries. A trigger names who set it, the agent or person it is for, and its project.
  • bWho sees it. A household owner sees everything, including what is private to another member. Anyone else sees triggers in their projects and triggers for agents they own, and a person also sees a trigger they set for themselves or one that is for them.
  • cChecked at the door. Loom applies this to callers from outside: a person, an agent, a machine, someone's own program. Loom's own parts read without asking.
