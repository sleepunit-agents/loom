Tempo

Triggers: what starts work without anyone asking. A trigger fires in code and drops an item in someone's inbox. A non-empty inbox is what starts an agent or notifies a person.

  • Lists what is standing and what is due.
  • Fires on a time, a pull request changing, an answer arriving or a job stopping.
  • Drops an item in an inbox, or runs an operation that needs no agent.
  • Holds an agent's triggers while the agent is paused.

How it works

Four parts, firing, the sweep, volume and settings

A trigger's four parts

  • sourcea time, a pull request changing, an answer arriving, a job stopping
  • lifespanuntil stopped, for today, the next time only
  • ownerwho set it
  • targetrun an operation, or drop an item in an inbox

A schedule is a standing time trigger. A lane is a standing time trigger with instructions. A one-off wake is a time trigger that fires once. Waiting on an approval is a once-only trigger on that answer.

Fire, inbox, start

triggerfiresinboxsettlesagent

A trigger fires in code, with no model. It drops an item in the recipient's inbox. After a short settle time, a non-empty inbox starts an agent's body or notifies a person, with everything waiting at once. Pausing an agent holds its triggers.

The sweep

  1. Changes2 open, oldest 3 days
  2. Tasks4 ready, oldest 6 days
  3. Approvals1 pending, 2 hours

Each part contributes a short list of what is open and how long it has sat. One session per recipient sorts them. When nothing is open, no session starts.

Volume

  • fullthe default
  • dimone line
  • mutehidden, and always ends

Each recipient sets a volume on an inbox item. Dim returns to full when the item changes or has sat long enough. Mute ends after a week by default. A change breaks dim but not mute. Being asked by name breaks both.

Three settings

  • settlehow long an inbox waits before waking its owner
  • dimhow long before a dimmed item returns to full
  • mutehow long a mute lasts: 7 days by default

The timings are settings a person can change, each with a default. Loom keeps a row only for a person or agent that has changed them.

Who can see this

ownerfor an agent or a personproject
  • aWhat it carries. A trigger names who set it, the agent or person it is for, and its project.
  • bWho sees it. A household owner sees everything, including what is private to another member. Anyone else sees triggers in their projects and triggers for agents they own, and a person also sees a trigger they set for themselves or one that is for them.
  • cChecked at the door. Loom applies this to callers from outside: a person, an agent, a machine, someone's own program. Loom's own parts read without asking.
