What we decided

Every decision behind this site, in plain words. Each one names the page where it shows up, so you can check that nothing is missing.

25 decisions in 5 groups.

The product

  • One program and one data folder, quick for someone else to install.

    shows up on: Outside programs

  • One API for the command line, the web app and agents.

    shows up on: Outside programs

  • A restart is an acceptable deploy.

    shows up on: Outside programs

  • The tiled desk is the product on a desktop screen. The phone does what the desk does, built after the desk is right.

    shows up on: The desk · Outside programs

  • Parts can be replaced, such as the task store or a bridge, because each is a module with a typed interface.

    shows up on: Outside programs · The front door

Conversations and chat

  • Everything is a conversation, and there is one conversations table.

    shows up on: Conversations

  • One inbox for everything sent to anyone, person or agent.

    shows up on: Inbox · Conversations

  • Every app also appears inline in chat.

    shows up on: Tasks · Approvals · Tempo · Changes · Inbox

  • Chat is how you control loom. Screens are for seeing.

    shows up on: The front door · The desk · Secrets · People and projects

  • A settings change or a dangerous action asked for in chat gets an approval card inline, with before and after. Ordinary work needs no card.

    shows up on: Approvals · Tempo · The front door

People and trust

  • A small team that trusts each other. The project is the unit of sharing. No fine-grained permissions.

    shows up on: People and projects

  • Household owners see everything, including another member's private thread.

    shows up on: People and projects · Conversations

  • Whatever is installed is trusted. Permission is checked only for callers from outside.

    shows up on: Signing in · Outside programs

  • An outside program has one door: the API with a token.

    shows up on: Outside programs

  • Every task has an owner.

    shows up on: Tasks

Data

  • A concrete data model in real columns, defined once in Drizzle. The database does the work.

    shows up on: How a tile gets its data

  • SQLite by default. The database is a configuration choice.

    shows up on: How a tile gets its data

  • One query endpoint in a community standard, GraphQL, generated from the same schema. Changes arrive as subscriptions over a websocket.

    shows up on: How a tile gets its data

  • Agents' memories are the only data loom treats as precious.

    shows up on: Memory

Running

  • The clock is part of tempo: triggers, the inbox as the pile, the sweep, volume.

    shows up on: Tempo · Inbox

  • Measuring is off unless a household owner turns it on. Loom is instrumented once in the standard way, and measurements go to a monitoring tool you already run, to loom's own store, or both. Agents can read the local store.

    shows up on: Measuring

  • There are always two programs, loom and a worker. Nothing runs inside loom itself. A worker may share loom's machine.

    shows up on: Machines and jobs

  • Tempo's timings are adjustable per person, with defaults.

    shows up on: Tempo

  • The runtime handles model accounts, runners and which model a body uses.

    shows up on: Models and accounts

  • An account's owner and household owners see its detail. Everyone else sees a summary.

    shows up on: Models and accounts

That is the end of the path.
