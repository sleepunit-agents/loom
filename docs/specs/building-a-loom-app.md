# Building a loom app

Use `web/src/kit` over the cojeev `components/ui` primitives. Colours come from look tokens; do not add per-look app styles. The kit works in Neon Noir, Low Light and Daylight.

- `AppFrame`: `title`, `actions`, `filters`, `crumb`, `go`, `where`, optional `lead`, `context`, `more`, and `about`. Use `header={false}` only when the surrounding page already supplies its AppHeader; `onTitle` preserves an interactive title such as Comms rename. Its header uses AppHeader and the breadcrumb primitives. `about` participates in the desktop's right-click Chat about this hook; the window menu still derives the page from its URL. Never offer chat for a list as though it were an item.
- `DrawerSplit` is the two-pane chat frame when a narrow desktop needs its list in a modal drawer. `useDrawerSplit({active, twoFrom, resetKey})` measures the app's own border box and owns the drawer state. Pass its result as `layout`, plus `label`, `list`, `reader` and `blank`; use `SplitDrawerButton` with `layout.drawer` in the reader header. Choose `twoFrom` for the reader's minimum usable width, and change `resetKey` on navigation. The reader keeps its React slot across resize; the open drawer makes it inert, traps Tab, closes with Escape or the scrim and restores focus after removing inert. Phone rendering may use the app's page flow with `active:false`.
- `List` groups rows under an accessible `label`, with an optional visible `title`. `ListTitle` supplies the same section heading separately and forwards heading attributes such as `id`. `Row` takes `title`, `meta`, `icon` (an icon or avatar), `status`, `trailing`, `actions`, `selected`, `unread`, and standard button attributes/ref. The row itself opens the item; `trailing` is noninteractive text and `actions` holds independently focusable sibling controls. Supply `data-row-menu` and handle `loom-menu` for actions; do not nest buttons. `layout="stack"` is for text-heavy lists. Pass `aboutAttr` for item chat. `LinkRow` preserves native anchor semantics for rows with `href` (and renders an inert row without one). Use `wrap` for full source text in details/previews; `tone` on Row/LinkRow gives a status its `bad`, `warn` or `ok` color.
- `Split` is a complete list/detail frame: folders, list title/count, search/filters, rows, detail and back navigation. Use it instead of wrapping it in another AppFrame. It measures its tile: three panes from 900px, two from 640px, one below. On a phone, opening pushes the reader over the list; Back/Escape restores focus. Arrow keys move rows. Existing imports from `split.tsx` remain compatible while apps migrate.
- `Empty` says what is absent and optionally how it gets here. Search: “Nothing matches …”. A first use: “No … yet” with a useful next step. `Loading` uses a live status; give a short verb (“Opening contact…”). `Error` says what could not load, a useful explanation and an optional `retry` callback. Use `compact` for an Empty inside a small panel. Empty/Error accept `framed={false}` inside a surface that already has its frame; do not add a pane-wide nested border. Never show an error as an empty result.
- `useCollection(name, query)` reads the tab's existing shared runtime, through the current page's CSRF context. `name` is a versioned record type such as `loom/project@^1`; `query` accepts the runtime's where/order/limit/fields/aggregates. It returns ordered `rows`, `status`, `loading`, `stale`, `error`, `coverage`, `withheld`, `more`, and `loadMore`. Check coverage before claiming a total. Surface unavailable/denied/error explicitly or use the app's documented page fallback. A stale copy never authorizes an action: retain action-specific liveness checks and server enforcement. No new poller, record cache, credentials or draft text belongs here. Respect the provider's continuation contract: `audience: ask` live payload queries are one bounded page, so this hook's subscribing `loadMore` is not a non-live transcript/history reader.

Keep data derivation and actions in the app. Start by moving its markup, then migrate its remaining read models in the same app pass. Changes and Inbox prove the row/state/Split path; their existing data and answer guards stay in place.

`npm --prefix web run lint` and the web build flag new app row/header/empty CSS outside the kit. `scripts/app-kit-legacy.json` is the frozen debt list, not a place to exempt new app styles; remove entries when migrating their owner. Domain visuals (a transcript, agent face, day histogram) remain app-owned.
