# Running houses on the server machine

Use one job-taking worker on the machine. Individual jobs consume slots on that worker. A second job-taking worker has a separate slot counter, account limits and recovery state. Neither a box label nor a placement need proves which code a worker will execute. Use the same house executor for a body started by a machine event, a schedule, a terminal handoff or a bridge. Install the co-located worker under a dedicated Linux account with a private rootless engine. Keep its engine socket, storage and account sign-ins separate from the server. Give that account no access to the server home, backups, administrative credentials, SSH keys or service-manager socket. A mount validator cannot discover copies, hard links or bind mounts provisioned under innocent-looking names. Restrict the operating-system account as well as configured mount sources. A diagnostics-only worker has zero job slots.

## Host work

This change retires host process bodies. The approved set of scheduled host programs starts empty. Existing scheduled house programs retain their isolated execution and pin checks. Machine reads retain their separate finite diagnostic catalog, audited requests and authorization checks. The machine-read broker does not reserve a job slot. An agent allowed to use a machine may already be allowed to inspect it. That permission cannot authorize a new host program.

A future host program requires all of the following to become one operation:

1. A signed-in owner approves an exact machine, agent, trigger, executable identity, literal arguments, allowed inputs and deadline. Loom records the member and the time from the authenticated interaction. A body acting on an owner's word cannot approve. A standing rule for another type of card cannot approve. Editing or re-creating a trigger invalidates its binding.
2. The server admits a distinct program firing, shares the machine's job-slot budget and binds the grant revision to its lease. It checks current authorization at claim and release. Revocation, owner removal, stale leases, ordinary jobs, guest rooms, held work and unverifiable provenance fail closed. Retries have distinct attempts under the same firing. Completed or uncertain effects must not be replayed without the program's own idempotency witness.
3. A local, operator-controlled registration fixes the executable and its dependencies outside directories writable by bodies. A content check followed by executing a mutable pathname leaves a race. A house commit and image digest identify bytes inside an image and convey no authority over an executable on the host.
4. Launch with a dedicated operating-system identity, a minimal environment, a fixed working directory, no interactive shell, a bounded deadline and reaping of the whole child group. Release only enumerated input fields. Apply scheduled-program result validation and credential screening before recording or delivering output. Never store raw stderr. Record grant, approving member, trigger, attempt, lease, machine and outcome even on refusal. A requested wake goes through normal house admission.

No current caller supplies these witnesses together. In particular, the owner-word rule for setting a scheduled house program admits a body, and the worker's fixed diagnostics run independently of job leases. Switching either path to a host executable would make it possible to run under a different authority than the owner reviewed. The two concrete state-changing requests in the lane inventory are resuming a backup timer and opening a login session. Keep these with the operator until a narrowly scoped program can prove the four steps above. There is no need for a free-form host model session.

## Capacity and storage

Start the server machine at one job slot. A slot limits concurrent jobs, not CPU use or the size of an image build. Reserve capacity for the live database and the server, measure peak build and job memory, and raise the slot count only against that measurement. Prebuild or canary one pinned house at a time with the core layers shared. Measure filesystem free space and engine usage before and after each build. Preserve the active image and rollback image. Stop admitting new builds if a complete measured rebuild plus rollback would consume the remaining space. The existing worker cleans its engine after builds, including unnamed images older than a day and build cache unused for a week. Give it a dedicated engine and quota before admitting a build on the server filesystem. Additional manual pruning requires separate operator approval.
